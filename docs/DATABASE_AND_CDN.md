# Database Schema & CDN Asset Reference

## 1. Cloud Firestore Database Architecture

The BooksBound backend relies on Cloud Firestore as its primary document database. The catalog is organized into two primary root-level collections:
- `categories` (8 root documents)
- `books` (24 root documents, expandable)

---

## 2. Collection & Document Specifications

### 2.1 `categories` Collection

Each document in `categories` represents a genre taxonomy item. Document IDs match the lowercase category identifier (e.g., `fiction`, `science`, `biography`).

#### Schema Definition

| Field Name | Type | Required | Description | Example |
| :--- | :--- | :--- | :--- | :--- |
| `name` | `string` | Yes | Human-readable title displayed in navigation pills and headings. | `"Fiction"` |
| `icon` | `string` | No | Material/Cupertino icon identifier for vector fallbacks. | `"menu_book"` |
| `color` | `integer` | No | 32-bit ARGB integer color hex value for category cards. | `4284612846` (`0xFF6200EE`) |
| `imageUrl` | `string` | Yes | Absolute CDN URL to category header artwork. | `"https://cdn.jsdelivr.net/.../fiction.jpg"` |
| `description` | `string` | No | Short editorial description of the category scope. | `"Novels, drama, and imaginative literature"` |

#### Standard Seed Categories (8 Documents)
1. `fiction`
2. `mystery`
3. `science`
4. `history`
5. `fantasy`
6. `romance`
7. `biography`
8. `technology`

---

### 2.2 `books` Collection

Each document in `books` represents an individual catalog title. Document IDs are randomly generated by Firestore (`Auto-ID`), or passed explicitly during migration.

#### Schema Definition

| Field Name | Type | Required | Description | Example |
| :--- | :--- | :--- | :--- | :--- |
| `title` | `string` | Yes | Full commercial title of the book. | `"The Great Gatsby"` |
| `author` | `string` | Yes | Full name of author(s). | `"F. Scott Fitzgerald"` |
| `genre` | `string` | Yes | Primary category name. | `"Fiction"` |
| `category` | `string` | Yes | Legacy alias matching `genre` for backward compatibility. | `"Fiction"` |
| `category_lowercase` | `string` | Yes | Trimmed and lowercased genre string for case-insensitive indexing. | `"fiction"` |
| `description` | `string` | Yes | Full synopsis / book summary. | `"A story of the fabulously wealthy Jay Gatsby..."` |
| `coverUrl` | `string` | Yes | Absolute CDN URL or Base64 data string for the cover image. | `"https://cdn.jsdelivr.net/.../the-great-gatsby.jpg"` |
| `price` | `number` (double) | Yes | Retail unit price in USD. | `12.99` |
| `rating` | `number` (double) | Yes | Average rating score from 0.0 to 5.0. | `4.5` |
| `isBestseller` | `boolean` | Yes | Flag for promotional placement in home screen carousel. | `true` |
| `isbn` | `string` | Yes | Standard 13-digit International Standard Book Number. | `"9780743273565"` |
| `releaseDate` | `timestamp` | Yes | Publication date stored as UTC Firestore Timestamp. | `Timestamp(seconds=172800, nanoseconds=0)` |
| `reviews` | `array<map>` | No | Embedded array of review objects (or kept empty in favor of subcollections). | `[]` |

## 3. CDN URL Conventions

All official assets are hosted in the GitHub repository [`chotabahi/book-app-assets`](https://github.com/chotabahi/book-app-assets) on branch `main` and served globally via the jsDelivr CDN.

### 3.1 Book Covers Path Convention
```
https://cdn.jsdelivr.net/gh/chotabahi/book-app-assets@main/covers/<book-slug>.jpg
```
- `<book-slug>` is the lowercased, hyphen-separated book title.
- Special punctuation is removed.
- Example: `"The Girl with the Dragon Tattoo"` -> `the-girl-with-the-dragon-tattoo.jpg`
- Complete URL: `https://cdn.jsdelivr.net/gh/chotabahi/book-app-assets@main/covers/the-girl-with-the-dragon-tattoo.jpg`

### 3.2 Category Assets Path Convention
```
https://cdn.jsdelivr.net/gh/chotabahi/book-app-assets@main/categories/<category_id>.jpg
```
- `<category_id>` matches the category document key.
- Example: `non-fiction.jpg`, `science.jpg`, `academic.jpg`
- Complete URL: `https://cdn.jsdelivr.net/gh/chotabahi/book-app-assets@main/categories/science.jpg`

## 4. Seeding Firestore via Node.js Script

The repository includes a dedicated seed utility: [`scripts/seed_firestore.js`](../scripts/seed_firestore.js). This script sets up the 8 standard categories and populates 24 books (3 per category) using proper CDN links and Firestore datatypes.

### 4.1 Prerequisites
Ensure Node.js `>= 18.0.0` is installed on your development machine:
```bash
node -v
```

### 4.2 Authentication Method 1: Using `serviceAccountKey.json` (Recommended for CI / Admins)

1. Open the [Firebase Console](https://console.firebase.google.com/).
2. Navigate to **Project Settings** > **Service accounts**.
3. Click **Generate new private key**.
4. Download the generated JSON file and rename it to `serviceAccountKey.json`.
5. Place `serviceAccountKey.json` in the root of your project directory:
   ```
   Flutter-Book-Store-App-main/
   ├── android/
   ├── lib/
   ├── scripts/
   │   └── seed_firestore.js
   ├── serviceAccountKey.json   <-- Placed here (automatically gitignored)
   └── pubspec.yaml
   ```
6. Install script dependencies (if not already installed):
   ```bash
   npm install
   ```
7. Execute the seed script:
   ```bash
   node scripts/seed_firestore.js
   ```

*Note: You can also specify an arbitrary key path via the environment variable:*
```bash
export GOOGLE_APPLICATION_CREDENTIALS="/absolute/path/to/my-key.json"
node scripts/seed_firestore.js
```

### 4.3 Authentication Method 2: Using Firebase CLI (`firebase login`)

If you don't have a service account file but have admin rights on the Firebase project:
```bash
npm install -g firebase-tools
firebase login
node scripts/seed_firestore.js
```
The script will automatically discover your active CLI OAuth access token located in `~/.config/configstore/firebase-tools.json` and authenticate against the Firestore REST API.
